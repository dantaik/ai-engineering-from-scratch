softmax 与 temperature：从裸分到骰子

承接《玩具 GPT 全流程走查》· 语境「我爱吃」之后的出口打分 · V = 10

随机不是温度产生的——随机来自「按概率抽签」这个动作。温度只负责在掷骰子之前改变签筒里各段的长度：softmax(z/T) 保序、只调悬殊。T = 0 是不掷骰子的特例，T = 1 是模型本色，T → ∞ 是纯瞎猜。

1 · logits：出口的裸分

走查里讲过：模型取最后一个位置的语境化向量（1×4），乘输出矩阵 U（4×10），得到 10 个实数——每个候选 token 一个分。这排数叫 logits：可正可负、没有范围、加起来不等于任何特定值，就是裸分。名字借自统计学的对数几率（logit = log-odds，sigmoid 的反函数），深度学习里泛指「概率化之前的分数」。API 里的 logprobs、logit_bias、temperature 全都工作在这一层。本篇通篇使用同一组裸分：

logits：苹果 3.1   香蕉 2.2   甜 0.5   我 0.3   ， 0.2   吃 0.1   很 −0.4   爱 −0.8   <EOS> −1.2   的 −2.0

2 · softmax：三步把裸分变概率

softmax(zᵢ / T) = e^(zᵢ/T) / Σⱼ e^(zⱼ/T)

第一步：每个 logit 除以 T        T=0.5 等于分数全体 ×2；T=2 等于全体 ÷2；T=1 原样
第二步：逐个取 e 的幂            把任意实数变成正数，指数放大差距
第三步：除以全体之和 Σ           归一化，V 个数加起来 = 1

从这张表读出 softmax 的三条性格：负分不等于零概率（「的」仍拿 0.4%，长尾永不清零——top-p/top-k 存在的理由）；只看分差不看绝对值（全体 logits 同加 100，概率纹丝不动，实现时先减最大值防溢出即源于此）；保序（裸分排名 = 概率排名，softmax 只调悬殊，从不翻盘）。

3 · 分水岭：只有 T = 0 是特殊处理，其余一律是抽签

温度的两种工作模式

T = 0：特判分支，恒定取最大。不构造概率、不掷骰子，直接 argmax——logits 最高者当选，完全确定，同一 prompt 每次生成一字不差。数学上它是 T → 0 的极限；工程实现里就是一条 if T == 0: argmax 的特殊处理，连 softmax 都不用算。这叫贪心解码（greedy）。

T > 0：一律按概率抽签。不管 T 是 0.01 还是 2，本质完全一样——都是随机采样，温度只影响概率分布的悬殊程度，不制造随机、也不关闭随机。哪怕 T = 0.01，「香蕉」在理论上仍有非零概率被抽中（约 e^(−0.9/0.01) ≈ 10⁻³⁹，小到宇宙尺度上也见不到一次，但机制上它一直在签筒里）。「确定」只存在于 T = 0 这一个特判点上。

贪心的确定性是双刃剑：适合数学、代码、信息抽取；但容易复读和僵硬——一旦落入循环就出不来，所以写作类任务不用它。

4 · 随机从哪一步进来：抽签

采样的机制：把 V 个概率排成一条 0 → 1 的线段，掷一个 0 ~ 1 之间的均匀随机数 u，落进谁的区间就选谁。骰子只在这一步出现。温度在骰子掷出之前调整各段的长度：

T = 0 贪心
苹果 1.00 —— 不掷骰子，直接取最大
T = 0.5
苹果 .846香蕉 .140
T = 1
苹果 .583香蕉 .237其余 7 个 .137
T = 2
苹果 .320香蕉 .204甜 .087其余 6 个 .389

段长的算法就是第 2 节的三步：T = 0.5 时全体 logits ×2 再 softmax（苹果 e^6.2 = 492.7，Σ = 582.2，492.7/582.2 = 0.846）；T = 2 时全体 ÷2（苹果 e^1.55 = 4.71，Σ = 14.72，4.71/14.72 = 0.320）。

「加了 temperature 就变随机」的准确含义——掷同一个随机数 u = 0.70：T = 0.5 时落在苹果段内（0 ~ 0.846）；T = 1 时落进香蕉段（0.583 ~ 0.820）；T = 2 时越过苹果、香蕉、甜、我（累计 0.690），落进「，」的地盘（0.690 ~ 0.765），输出一个逗号。同一个骰子，温度不同，地价不同，命运不同。骰子一直都在，温度决定它有多大杀伤力。

5 · 温度的全域图景：从必然到瞎猜

一个公式看穿所有情形——任意两家的概率之比 = e^(分差/T)（分母 Σ 在做比时约掉了）。分差固定是 0.9（苹果 − 香蕉），T 只是它的分母：

温度苹果香蕉的读法
T = 01.00000one-hot：强者通吃（必然）
T = 0.50.8460.1400.000比模型本身更自信
T = 10.5830.2370.004模型本色：训练学的就是这个分布
T = 20.3200.2040.025分差被压扁，长尾抬头
T = 50.1710.1430.062肉眼可见地滑向均匀
T → ∞0.1000.1000.100uniform：人手 1/V，纯瞎猜

三个极端各有一句话：T → 0，分差 ÷ 极小数被放大到无穷，概率比 → ∞，最高分独占整条线段；T = 1，softmax(z/1) 就是 softmax(z)，这是模型训练时真实学到的分布；T → ∞，所有 z/T → 0，e⁰ = 1 人手一份，每个 token 得 1/V = 0.1——连 logit 为 −2.0 的「的」也拿 10%，模型学到的一切信息被彻底抹平。所以调低温度是在「比模型更自信」，调高温度是在稀释模型的置信度——「高温更有创意」和「高温更容易胡说」是同一件事的两面。

6 · 自检与工程注脚

两条自检规则（不用算分母就能验表）

① 任意两家概率比 = e^(分差/T)。验证：T = 1 时苹果/香蕉 = 0.583/0.237 = 2.46 = e^0.9 ✓

② 每行概率之和必须为 1（0.583 + 0.237 + 0.043 + 0.137 = 1.000 ✓）——分母 Σ 的存在就是为了这个。

自己重算整张表只要三行（改 T、改 logits 随意实验）：

import math
z = {'苹果':3.1,'香蕉':2.2,'甜':0.5,'我':0.3,'，':0.2,'吃':0.1,'很':-0.4,'爱':-0.8,'EOS':-1.2,'的':-2.0}
T = 2
e = {k: math.exp(v/T) for k, v in z.items()}; s = sum(e.values())
print({k: round(v/s, 3) for k, v in e.items()})

工程注脚：API 通常把 T 限制在 0 ~ 2，再高就是花钱买瞎猜；实践中很少裸抽签，会配 top-p / top-k 先把长尾逐出签筒再抽——防止高温下抽中「的」这类明显不通的尾巴；创意任务常用 T ≈ 0.7 ~ 1.0，数学与代码用 T = 0。
