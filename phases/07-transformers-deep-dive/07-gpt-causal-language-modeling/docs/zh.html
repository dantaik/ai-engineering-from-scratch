PHASE 7 · GPT — CAUSAL LANGUAGE MODELING · 中文笔记

玩具 GPT 全流程走查

d = 4（宽度）　L = 3（层数）　V = 10（词表）　参数 656　prompt「我爱吃」(n = 3)

整个 GPT 就是一个函数——f(前文的 n 个整数) → 下一个位置的 V 个概率。形状只在入口（V×d 查表）和出口（d×V 打分）各变一次，中间 L 层恒为 n×d；所谓生成，就是把自己的输出粘回输入末尾，再调用一次 f。

1 · 舞台：一个 10 词的迷你世界

词表小到可以全部列出来。每个 token 有一个编号（ID）——编号本身没有任何意义，1 号和 2 号只是门牌相邻：

0·<EOS>1·我2·爱 3·吃4·苹果5·香蕉 6·很7·甜8·的9·，

输入 prompt「我爱吃」，分词后得到 3 个整数（n = 3）：

我爱吃 → [1, 2, 3]

形状事实

中间无论叠多少层，数据的形状恒为 n×d——每个 token 一行、每行 d 个数。会变形状的只有两处：入口把「1 个编号」变成「d 维坐标」，出口把「d 维坐标」变成「V 张选票」。

2 · 逐个环节：输入、输出、含义

入口：查嵌入表（编号 → 坐标）3 个整数 → 3×4

嵌入表 E 的形状是 V×d = 10×4——整张表就 40 个数字。输入 [1, 2, 3]，动作只是取出第 1、2、3 行，得到 3×4 的矩阵 X⁰，例如 E[1] = [0.2, −1.1, 0.5, 0.9] 就是「我」的 4 维坐标。每行再加上位置信息（「我是第几个字」），否则模型分不清「我爱吃」和「吃爱我」。本质是查表，没有计算。

块内单元 A：注意力——唯一让 token 交流的地方3×4 → 3×4

每行向量分身三份：Q（我在找什么）、K（我是什么）、V（我能提供什么），各由一个 4×4 矩阵变换而来。所有 Q 对所有 K 打分，得到一张 n×n 的相关性表。n = 3 时只有 9 个格子，整张表如下：

看「我」看「爱」看「吃」
「我」行1.00✗✗
「爱」行0.350.65✗
「吃」行0.200.300.50
允许注意（每行经 softmax 成权重） ✗ 因果掩码：不许看未来

「吃」行的读法：它决定听 50% 的自己、30% 的「爱」、20% 的「我」，按权重对各家的 V 向量加权求和——「吃」的新向量里从此掺进了前文的信息。右上角被遮住的三个格子就是「因果」二字的全部含义：任何位置只能看自己和过去。这张表也正是注意力 O(n²) 成本的本体。

块内单元 B：FFN——各自消化，互不交流3×4 → 3×4

每行独立通过一个小网络：4 维 → 16 维（升维 4 倍）→ 非线性 → 压回 4 维。不看别的行，就地加工刚从注意力收集来的信息。两个单元都是残差式的：输出 = 输入 + 修正量——每层只在原坐标上「修一笔」，这是几十层深的网络不失真的关键。

三块叠加：形状不变，语境化程度在变

X⁰ → 块1 → X¹ → 块2 → X² → 块3 → X³，形状全程 3×4。变的是每行内容的深度：第 0 层的「吃」只是字典里的吃；到第 3 层，「吃」这一行已经变成了「『我爱』之后的那个吃，正在期待一个食物宾语」。

出口：最后一行 → V 张选票1×4 → 10 个概率

预测下一个 token，只取 X³ 的最后一行（「吃」的最终 4 维向量），乘以输出矩阵 U（4×10），得到 10 个 logits（裸分，可正可负）；除以温度 T、过 softmax 变成 10 个概率；掷骰子采样：

「吃」的 1×4 → ×U → 10 个 logits → softmax → 苹果 0.61 · 香蕉 0.24 · … → 采样 → 苹果

出口之后怎么选：T = 0 特判，其余抽签

没有随机因素时，最高分就是下一个词——这是 T = 0 的贪心特判，恒定取最大、完全确定；T > 0 时一律按概率抽签，温度只影响概率分布的悬殊程度，不制造随机、也不关闭随机。完整拆解（softmax 三步手算全表、四种温度的签筒对比、同一个骰子 u = 0.70 的三种命运、温度全域图景）单独成篇：附录 · softmax 与 temperature：从裸分到骰子 →

3 · 核心问题：预测第 2 个 token 和第 1 个有什么不同

概念上：没有任何不同。模型是无状态的——它没有「记忆」这个器官，衔接方式简单粗暴：把刚生成的 token 粘回输入末尾，整条流水线重跑一遍。这就是「自回归」（autoregressive）的字面意思：自己回头喂自己。

步骤输入序列注意力输出
1 我爱吃 3×3 苹果
2 我爱吃苹果 4×4 很
3 我爱吃苹果很 5×5 甜
本步全量计算 不重算——K/V 从缓存读 新 token（唯一要算的） 输出

两步之间的全部区别：序列长一格、注意力表大一圈、取的是新的最后一位。工程上，第 2 步不必真的全部重算——KV cache 登场。

为什么缓存是合法的 —— 因果掩码的深远后果

前文 token 永远看不到新 token ⇒ 「我 / 爱 / 吃」的表示在每一步都一模一样 ⇒ 算一次，存起来，永远复用。之后每步只算新 token 自己的 Q/K/V，新 Q 对缓存里全体 K 打一行分（1×n），而不是重算整张 n×n 的表。

账单形态：prefill（第 1 步）整个 prompt 一次算完，付 O(n²)——首 token 慢在这里；decode（其后每步）只算一个新 token，付 O(n)——后续 token 快在这里。KV 缓存随 n 线性长大，是长上下文吃显存的元凶。

4 · 训练 vs 推理：n 道并行考题

推理时只取最后一行去预测；训练时 n 行全都要——「我」行预测「爱」、「爱」行预测「吃」、「吃」行预测「苹果」（错一位对答案，即 shift-by-one），每行各算一份交叉熵。一条 2048 长的打包序列就是 2048 道并行考题。这就是「训练并行、推理串行」：训练一遍前向学 n 个位置，推理一遍前向只吐 1 个字——因果掩码保证了训练时的并行不会作弊（每道考题都看不到自己的答案）。

5 · 参数总账：玩具和 Llama 是同一张图

每块：  注意力 Q/K/V/O 四个 4×4 = 64      FFN 4×16 + 16×4 = 128      共 192
三块：  192 × 3 = 576   恰好 = 12·L·d² = 12 × 3 × 4²（公式分毫不差）
两头：  嵌入 10×4 = 40   输出 4×10 = 40（有的模型两者共享一张表）
合计：  约 656 个参数

真实的 Llama-3-8B 就是同一张图，把数字换成 d = 4096、L = 32、V = 128,256，再把注意力换成多头（4096 维切成 32 个头并行）而已——8B 个参数、一样的入口出口、一样的 n×d 形状恒定、一样的「粘回队尾」循环。你在这个 656 参数玩具上建立的每一条直觉，原样适用。
