PHASE 7 · 02 SELF-ATTENTION FROM SCRATCH · 中文笔记

注意力机制单独拆解：查询、键、值与多头

前置：玩具 GPT 走查（那里把注意力放在整条流水线里过了一遍）　本篇例子 d_k = d_v = 2　真账 Llama-3-8B

注意力回答一个问题：当前这个词，该从前文哪些词那里搬多少信息。答案不是学死的参数，而是每次前向按内容当场算出来的一张权重表；Q、K、V 三个投影矩阵是它的全部道具，softmax(QKᵀ/√dk + M)V 是它的全部数学。

1 · 它在整栋楼里的位置：搬运，不是加工

每个 transformer 块只有两个单元，分工干净：注意力跨行搬运（token 之间唯一的信息通道），FFN 逐行加工（每行独立消化，互不交流）。走查页已经从 KV cache 反推出这一点——正因为前文行永不回头看新行，它们的表示才能缓存复用。本篇把搬运这一半单独拎出来，回答「为什么长这样」。

先钉死一个区分：参数 vs 激活

WQ、WK、WV、WO 是参数——训练学出来、写死在权重文件里、对所有输入相同。而那张「谁看谁、看多少」的注意力权重表是激活——每个新输入当场重算、用完即弃、句句不同。「动态路由」四个字的全部含义就在这：路由表不是学出来的常数，是运行时按内容算出来的函数值。

2 · 它要解决的问题：按内容寻址

「那只猫追着球跑，它累了。」——「它」指谁？人会立刻回答猫，理由是语义（球不会累），不是位置。任何写死的规则——「看前一个词」「看第 3 个位置」——都会在下一个句子上翻车：相关性本身取决于内容，所以相关性必须按内容当场计算。

用什么算？老朋友：点积 = 方向对齐程度（第一阶段线性代数，在嵌入、在出口打分之后，这是它第三次上岗）。给每个词一个向量，两两做点积，就得到一张按内容算出来的相关性表——这就是注意力的骨架。剩下的问题只有一个：拿哪个向量去点积？

3 · 为什么是三个矩阵：找人、被找、交货是三件事

每行向量 x 进入注意力时分身三份，各由一个参数矩阵投影而来：

q = x · W_Q   我在找什么        （query   ：主动发问的检索条）
k = x · W_K   我以什么面目被找   （key     ：挂给别人看的标签）
v = x · W_V   找到我后我交出什么 （value   ：真正被搬走的内容）

上一节两张表的教训在这里重演：同一个对象，角色不同就需要不同的表示——入口 E 和出口 U 是两个角色，这里干脆一分为三。反过来想更清楚：如果不分家，直接拿 x 自己当 q、k、v，会得两种病——

对称病：点积可交换，x猫·x球 ≡ x球·x猫，「猫看球」和「球看猫」被迫永远同分，可指代关系明明是有方向的。自恋病：对角线 x·x = ‖x‖² 天然是全表大户，每个词最关注自己，搬运通道形同虚设。WQ ≠ WK 一举治好两种病（打分变成 xiWQ·xjWK，既不对称、对角线也不再特殊）；WV 则让「交付的内容」独立于「检索用的标签」——图书馆里书脊标签和书的内容本就不是一回事。

4 · 手算一遍：分数 → 缩放 → 掩码 → softmax → 加权和

三个 token「猫 追 球」，dk = dv = 2。q/k/v 本应由 x 乘三个 W 得到（走查页演过那一步），这里直接给出投影结果，专注机制本身。数字是编造的教具，全部经程序复算：

位置tokenq（找什么）k（被怎么找）v（交什么货）
1猫(0.6, −0.1)(1.0, 0.2)(0.8, −0.2)
2追(0.9, 0.8)(−0.4, 1.0)(−0.1, 0.9)
3球(1.2, 0.4)(0.3, −0.5)(0.4, 0.3)

每个位置拿自己的 q，去和自己及之前所有位置的 k 点积。三个位置三种处境：

位置 1「猫」：候选只有自己。softmax 在单元素上恒等于 1，输出就是 v₁ = (0.8, −0.2)。第一个 token 永远没得选——它的注意力输出只含它自己。

位置 2「追」：两个候选。q₂·k₁ = 1.06，q₂·k₂ = 0.44；除以 √2 得 0.750 和 0.311；softmax 后权重 0.608 / 0.392；输出 = 0.608·v₁ + 0.392·v₂ = (0.447, 0.231)。

位置 3「球」：全表登场，逐步走完——

步骤对「猫」对「追」对「球」（自己）
① 点积 q₃·kj1.28−0.080.16
② ÷√dk = √20.905−0.0570.113
③ ex2.4720.9451.120　（合计 Z = 4.537）
④ 权重 = ex/Z0.5450.2080.247　（和 = 1）

⑤ 按权重把三家的 v 加权求和：out₃ = 0.545·v₁ + 0.208·v₂ + 0.247·v₃ = (0.514, 0.153)。

读法：「球」的查询向量和「猫」的键高度同向（点积 1.28 一骑绝尘），于是新的「球」向量里 54.5% 的成分从「猫」搬来——「球」这一行从此记住了「有只猫在追我」。输出永远是前文 value 的加权平均（权重非负、和为 1），权重由「我的问题」和「你的标签」的对齐程度决定。

公式收束

Attention(Q, K, V) = softmax(QKᵀ/√d_k + M) · V　——　QKᵀ 是①（所有 q 对所有 k 的点积表，n×n），√dk 是②，M 是下文的因果掩码，softmax 是③④（逐行），最后乘 V 是⑤。你刚才手算的就是这一行符号的全部内容。

5 · 为什么除以 √d_k：写死在架构里的温度

softmax 前先除一个数——这个动作你在采样那篇见过：除数就是温度。√dk 是一个不学习、不可调、写死在架构里的固定温度，专治一种病：

点积是 dk 个乘积之和。若 q、k 各分量独立且方差为 1，则 q·k 的方差恰好是 dk——维度越高，裸分天然越悬殊。dk = 64 时典型分数已到 ±8，两个候选轻松差出 16 个 logit，概率比 e¹⁶ ≈ 890 万 : 1——softmax 饱和成独热分布，梯度趋近于 0，训练学不动（这正是采样篇里 T 太小的画面，只不过发生在模型内部）。除以 √64 = 8，方差拉回 1，softmax 回到灵敏区。

工程注脚：这是训练稳定性设计——推理时它只是个常数，但没有它，训练在第一步就瘫在饱和区里。

6 · 因果掩码：把未来写成 −∞

解码器的规矩「不许看未来」不是靠 if 语句，而是在 softmax 之前把非法格子的分数加上 −∞：

看「猫」看「追」看「球」
「猫」行0−∞−∞
「追」行00−∞
「球」行000
0 = 分数原样通过 −∞ = 该格概率恰好为 0

为什么在分数上动手，而不是算完概率再清零？因为 e−∞ = 0（采样篇的极限又用上了）：被掩的格子经 softmax 精确得 0，且每行剩余概率自动归一——若在概率上清零，「和 = 1」被破坏，还得手工再归一化。一个 −∞ 同时办妥两件事。

这张小小的上三角掩码撑起了走查页的两个结论：训练时一次前向 = n 道并行考题（每行看不到自己的答案），生成时前文表示永不改变 = KV cache 合法。

7 · 多头：32 张粗表，胜过 1 张细表

真实模型不做一次大注意力，而是把 d 切成 h 份并行做 h 次小注意力。Llama-3-8B：d = 4096 切成 32 个头，每头 128 维，各自独立跑完上面全套（各头的固定温度是 √128 ≈ 11.3），结果拼接回 4096 维再过 WO 混合。

多头 ≠ 多参数

WQ/WK/WV/WO 的总形状不因头数改变——多头只是把大矩阵按列分成 32 组，各组独立打分而已。参数账一分钱不多花，多出来的是路由的多样性。

为什么多样性值钱？一个头一张 n×n 权重表，每行 softmax 和为 1——这是硬约束：一张表想同时「盯住语法主语」又「盯住指代对象」，两股注意力就会互相稀释。32 个头 = 同时维护 32 张互不干扰的关系表，各学各的模式（对训练好的模型做解剖，确实能观察到分工：有的头专盯前一个词，有的头专做指代回连，有的头几乎只看句首）。单头 4096 维是一张超精细的表，但只有一张；32 张 128 维的粗表赢在能同时表达 32 种「谁看谁」。

玩具走查是单头（d = 4 切不动），所以那里看不见这一层。

8 · 现代形态：围绕 KV cache 的三次手术

生成时 K、V 要进缓存（Q 用完即弃），缓存大小 = 2 × 层数 × KV 总维度 × 上下文长度 × 每数字节数。上下文一长，这笔显存迅速压过参数本身，于是现代注意力的改造全都冲着 KV 来：

手术做法代价与收益
GQA
分组查询		32 个 Q 头共享 8 组 K/V（Llama-3-8B：WK/WV 从 4096×4096 缩到 4096×1024）cache 直接 ÷4：FP16 下每 token 128 KB，128K 上下文 ≈ 16 GB（不做 GQA 是 64 GB）；质量几乎无损
MQA
多查询		全部 Q 头共享 1 组 K/V（GQA 的极端版）cache ÷32，但质量有可感损失——GQA 正是它和全量之间的折中
MLA
潜在注意力		DeepSeek 系：K/V 先压进一个低秩隐向量，用时再展开cache 再砍约一个数量级，代价是多一次展开计算

还有一刀不动数学、只动实现：FlashAttention 分块计算，让 n×n 的分数表永远不完整落进显存——O(n²) 的计算量还在，但显存瓶颈解除。而 O(n²) 本身动不了：每个新词都要和全部前文打一遍分，这就是长上下文 prefill 贵、「首 token 慢」的物理根源（成本篇那笔账的实体）。

一个反差值得记住：这架构以 attention 命名（Attention Is All You Need），账上七成参数却在 FFN——搬运本身不贵，贵的是搬来之后的加工；但全模型只有搬运这一个环节跨位置。删掉它，每个词永远活在自己的字典释义里。

本篇故意没讲的一件事

把上面小例子的三行 k/v 连同掩码一起换个顺序，每个位置的输出分毫不变——点积注意力天生对顺序失明，它只认内容不认座位。可「猫追球」和「球追猫」显然不是一个意思。谁告诉注意力「猫在球前面」？位置编码（现代主流是 RoPE）——那是下一课（04-positional-encoding）的主角，也是玩具走查里「每行再加上位置信息」一句话背后的整个世界。
