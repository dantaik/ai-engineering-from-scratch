浮点数把比特花在哪里

它们都是浮点数,区别只有一个:有限的比特怎么分配。指数位买"范围",尾数位买"精度"。这一页讲清楚三代格式的构造与取舍,以及在训练、推理里分别怎么用。

符号位 —— 正负 指数位 —— 决定范围(能表示多大/多小) 尾数位 —— 决定精度(有效数字)

同一比例下的五种格式。注意 BF16 的符号位 + 指数位与 FP32 完全对齐——它就是把 FP32 的尾数直接砍到 7 位得到的,所以两者能表示的数值范围一模一样。

黄金基准。如今在深度学习里主要当安全网:master 权重、optimizer 状态、累加器、归约统计。

BF16

Basics

60 秒读懂浮点数

一个浮点数由三个字段拼成,本质上就是二进制的科学计数法:

数值 = (−1)符号 × 1.尾数2 × 2指数 − bias

指数字段决定小数点"飘"多远,所以指数位数决定动态范围;尾数记录有效数字,所以尾数位数决定精度。bias 是个固定偏移,让指数字段能用无符号整数存负指数。两个码位有特殊用途:指数全 0 表示次正规数(切换成 0.尾数 模式,把 0 附近铺满),指数全 1 保留给 ±∞ 和 NaN。

解剖一个例子:π 在 FP32 里长这样

1指数 8尾数 23
符号 0 → 正数 指数 100000002 = 128 → 实际指数 128 − 127 = 1 尾数 → 1.100100100001111110110112 ≈ 1.5707964 合成:1.5707964 × 21 = 3.1415927(与真值只差 8.7×10−8)

四个高频术语

bias(指数偏置):存储值 = 实际指数 + bias。FP32/BF16 是 127,FP16/E5M2 是 15,E4M3 是 7。

ε(机器精度):1.0 和下一个可表示数的间距,等于 2−尾数位数。它衡量"相对误差的粒度"。

次正规数:指数全 0 时的特殊模式,牺牲精度换取更接近 0 的表示,避免"突然掉到 0"。

动态范围:最小正数到最大数横跨多少个数量级,几乎完全由指数位数决定。

Format · 1985

FP32:通用计算的基准

IEEE 754 单精度。1 + 8 + 23 的分配横跨约 76 个数量级,给出约 7 位十进制有效数字——对绝大多数工程问题"精确到无感",四十年来是科学计算、图形、游戏的通用货币。

3.4×10³⁸最大有限值
1.2×10⁻³⁸最小正规数(次正规到 1.4×10⁻⁴⁵)
1.2×10⁻⁷ε:1.0 附近的间距
≈7.2 位十进制有效数字

深度学习的意外发现是:神经网络对精度远不如对范围敏感。权重和激活承载的信息量远低于 23 位尾数,矩阵乘可以放心地降精度。于是 FP32 的角色从"全程参与"退到关键位置的安全网:

Master 权重与 optimizer 状态——一步更新量 lr×grad 相对权重常在 10−5 量级,比 BF16 的 ε 还小,低精度下会被整个吞掉,所以权重的"账本"必须记在 FP32 里。

累加器——tensor core 做 BF16/FP8 乘法时,乘积仍以 FP32 相加;softmax、LayerNorm、梯度 allreduce 这类长求和同理,否则误差随长度线性放大。

Format · Google Brain, 2018

BF16:砍尾数,不砍指数

第一代混合精度训练用的是 FP16(1+5+10)。它的痛点不是精度,而是 5 位指数:最大只到 65504——梯度或 logits 一越界就变成 inf,于是需要 loss scaling 这种"全局手动挡"来回搬运数值范围。

Google Brain 的解法粗暴而优雅:把 FP32 直接截掉低 16 位。指数保持 8 位,范围与 FP32 一字不差;尾数只剩 7 位,ε 从 10−7 涨到 0.0078。深度学习恰好"吃范围、不吃精度":梯度分布横跨十几个数量级,而单个数值 2~3 位有效数字就够用。

π 在 BF16 里:3.140625(误差 −0.031%)

1指数 8尾数 7

前 16 位与上面 FP32 的 π 完全一致——FP32 ↔ BF16 的转换只是截断/补零,硬件上几乎免费。

3.4×10³⁸最大值,与 FP32 同级
0.0078ε:精度只有 2~3 位十进制
免 loss scaling范围同 FP32,基本不上溢

TPU v2 首发,NVIDIA 自 A100 起全线支持,新款 x86(AVX-512 BF16 / AMX)和 Apple silicon 也有。2026 年的今天,BF16 是大模型训练的默认计算精度,也是推理精度的事实基线;FP16 则退守老硬件(V100、20 系)和部分推理场景。

FP8:一种位宽,两种布局

再砍一半,只剩 8 个比特,"怎么分"不再有唯一答案。标准干脆给了两种布局,按用途各取所需——前向要精度,反向要范围:

E4M3 前向:权重、激活

1+4+3,bias 7。精度优先:放弃 ±∞(指数全 1 也用来表示数值,只留两个 NaN 码位),把最大值推到 448。

π → 1.101₂ × 2¹ = 3.25(误差 +3.5%)

0.00195最小次正规数
无 ∞越界即 NaN(常配饱和模式)

E5M2 反向:梯度

1+5+2,bias 15。范围优先:完整 IEEE 语义(±∞、NaN),范围与 FP16 同级,适合动态范围大、又不怕粗的梯度。

1指数 5尾数 2

π → 1.10₂ × 2¹ = 3.0(误差 −4.5%)

为什么 FP8 必须配"缩放因子"

E4M3 的正数只覆盖 [0.00195, 448]——4~5 个数量级,而一层激活/梯度的分布会随训练不断漂移。直接 cast 等于把一幅宽画从两头裁掉。做法是给每个张量(或每小块)配一个 FP32 缩放因子 s:存 x/s 的 FP8 编码,算完再乘回来,让数据始终落在格式的"甜区"里。s 的来源有两派:按历史 amax 估计(NVIDIA Transformer Engine 的 delayed scaling),或者直接按块实时统计(DeepSeek-V3:激活 1×128 tile、权重 128×128 block)。

E4M3 全部 126 个正数值,画在 0 → 448 的线性轴上(每根线一个可表示值):

064128192256320384448

浮点网格在对数意义下均匀:0~1 之间挤了 55 个值,而 256~448 之间只有 7 个、相邻间隔 32。缩放的目的就是把张量的主体挪进左边的密集区。

≈2×H100 上 FP8 GEMM 相对 BF16 的峰值吞吐;显存带宽与通信量同时减半
671BDeepSeek-V3(2024)用细粒度缩放 + FP32 累加完成 FP8 预训练,证明大规模可行

两个值得知道的细节:DeepSeek-V3 发现 Hopper 的 FP8 tensor core 内部累加精度有限,于是每 128 个乘积就搬到 CUDA core 用完整 FP32 再累加一次;对比 INT8,FP8 的对数网格天然更宽容激活里的离群值,校准压力小得多。再往下走是 4 位:Blackwell 的 NVFP4 / MXFP4 用"每 16/32 个数共享一个缩放因子"的微缩放块格式,把缩放的思想直接做进了数据类型——gpt-oss 就是以 MXFP4 发布的。

Practice

工程实践:怎么选

日常训练 / 微调

2026 年的默认答案,不需要理由的那种。

BF16 autocast + FP32 master 权重 / optimizer 状态;归约与 loss 用 FP32

大规模预训练(H100 及以上)

GEMM 提速 ≈2×、激活显存减半;代价是要管好缩放因子并盯住 loss 曲线。

FP8 GEMM(前向 E4M3 / 反向 E5M2)+ per-tensor 或 per-block scaling + FP32 累加

推理部署

权重量化近乎无损,KV cache 是第二大显存头,别忘了它。

权重 FP8(Hopper+ 近无损)或 INT4/AWQ;KV cache 可 FP8;用 BF16 基线校对精度

老硬件(V100 / 20 系)

没有 BF16 单元,回到上一代方案。

FP16 autocast + GradScaler(动态 loss scaling),溢出跳步

常见的坑

  • BF16 的 ε = 0.0078:在 BF16 里 1 + 0.003 == 1。把 optimizer 状态、loss 累加或 running mean 放 BF16,会静默吞掉小更新——这类"账本"必须 FP32。
  • FP16 的天花板是 65504:梯度一炸就 inf,必须动态 loss scaling。BF16 对上溢基本免疫,但精度更粗——两者的 loss 曲线本来就会有微小差异,不是 bug。
  • FP8 不能裸 cast:不配缩放因子,张量两头会被大面积裁掉。per-tensor 不够稳时上 per-block(DeepSeek-V3 用激活 1×128、权重 128×128)。
  • 长求和永远 FP32 累加:softmax、LayerNorm、attention logits、梯度 allreduce。低精度求和的误差随长度线性放大。
  • E4M3 没有 ∞:越界产出 NaN。FP8 训练里排查 NaN,第一嫌疑人是缩放因子过期/过大,而不是模型本身。
  • 省显存 ≠ 只看权重:Adam 全家桶(FP32 master + 两个动量)约 16 字节/参数;推理时 KV cache 常比权重还大。算账要算全。
# 日常配方:BF16 autocast(A100 及以上)
with torch.autocast("cuda", dtype=torch.bfloat16):
    loss = model(batch).loss      # 矩阵乘走 BF16,tensor core 内部 FP32 累加
loss.backward()                   # 不需要 GradScaler:BF16 不像 FP16 那样容易上溢
optimizer.step()                  # optimizer 状态与 master 权重保持 FP32

# 追吞吐:FP8(Transformer Engine,H100 及以上)
import transformer_engine.pytorch as te
from transformer_engine.common.recipe import DelayedScaling, Format

with te.fp8_autocast(enabled=True, fp8_recipe=DelayedScaling(fp8_format=Format.HYBRID)):
    out = te_model(batch)         # HYBRID:前向 E4M3,反向梯度 E5M2
